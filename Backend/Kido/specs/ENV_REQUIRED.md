# ContextLock Environment Requirements

This file tells the coding agent what it may ask the human to provide. The project is **Sepolia-only** during the hackathon. Never use a personal/mainnet private key.

## Ask the human for these first

```dotenv
# Network
SEPOLIA_RPC_URL=
SEPOLIA_CHAIN_ID=11155111

# Disposable TESTNET keys only. Prefer separate keys.
DEPLOYER_PRIVATE_KEY=
CAPABILITY_ISSUER_PRIVATE_KEY=
AGENT_PRIVATE_KEY=
RELAYER_PRIVATE_KEY=

# Local app
DATABASE_URL=file:./contextlock.db
BROKER_PORT=8787
WEB_PORT=3000
NEXT_PUBLIC_CHAIN_ID=11155111
NEXT_PUBLIC_BROKER_URL=http://localhost:8787
LOG_LEVEL=info
```

### Funding requirement
`DEPLOYER_PRIVATE_KEY` (and `RELAYER_PRIVATE_KEY` if separate) need enough **Sepolia ETH** for deployment and demo gas. The agent wallet itself should hold minimal/no treasury value. Use faucet/test assets only.

## ENSv2 phase

The human must provide **one** of:

1. an ENSv2 Sepolia parent/name they control and permit the project to use; or
2. permission to let the build scripts register/configure a fresh test name with the disposable deployer.

The agent MUST use the current ENSv2 Sepolia docs to discover canonical deployments and current registration requirements. Do not ask the user to paste contract addresses copied from this document. Generated values such as agent subregistry/resolver addresses go in `deployments/sepolia.json`, not `.env` unless a runtime adapter needs them.

Possible runtime variables after deployment (generated by the agent):

```dotenv
ENS_ROOT_NAME=
ENS_AGENT_NAME=
ENS_AGENT_REGISTRY_ADDRESS=
ENS_AGENT_RESOLVER_ADDRESS=
CONTEXTLOCK_POLICY_REGISTRY_ADDRESS=
CONTEXTLOCK_GATEWAY_ADDRESS=
CONTEXTLOCK_AUTH_REGISTRY_ADDRESS=
CONTEXTLOCK_EXECUTOR_ADDRESS=
```

## Chainlink CRE phase

The human needs a Chainlink CRE account/login as required by the current CLI. The agent should first run the official simulator with **fake secrets**. Live Confidential Workflow access may require beta enrollment; lack of live access is a blocker for live deployment, not for simulator evidence when the current prize rules accept simulation.

If the current template requires an Ethereum key for on-chain CRE actions, use a disposable testnet-only key:

```dotenv
CRE_ETH_PRIVATE_KEY=
```

For simulator-only confidential values, use fake values and follow the current `secrets.yaml` mapping pattern. Example names (actual values are test data, not production secrets):

```dotenv
SECRET_POLICY_JSON=
SECRET_RISK_API_TOKEN=
```

Do **not** log real secrets inside a TEE handler. Do **not** treat the simulator as a real TEE.

## Ledger Key Ring phase

The human must have:

- a supported physical Ledger device;
- the device unlocked and appropriate Ethereum/device app available when the current SDK requires it;
- Ledger Agent Stack / wallet-cli installed by the agent following current docs;
- a strong local Key Ring password exposed only at runtime as:

```dotenv
WALLET_PASS=
```

`WALLET_PASS` MUST NOT be committed or passed literally in shell commands. Prefer a local shell/OS secret manager. The agent may generate a harmless mock protected-service token and encrypt it into the Key Ring. Do not use a real API credential for the hackathon proof unless necessary.

For DMK/Clear Signing, the user provides the physical device interaction, not a Ledger private key. **Never ask for a Ledger seed phrase or private key.**

## Optional external demo inputs

These are optional and MUST NOT block the core three-sponsor build:

```dotenv
# Only if adding a real external risk API after the local/mock path works.
RISK_API_URL=
RISK_API_KEY=

# Only if adding a separate DeFi adapter after core security passes.
DEFI_TARGET_ADDRESS=
```

## Values the coding agent must generate itself

Do not bother the human for: contract addresses after deployment, hashes, nonces, DB IDs, mock policy values, mock API tokens, local ports, test fixtures, CRE request IDs, policy commitments, deployment JSON, or ephemeral test accounts that can safely be generated locally.

## Safety check before any transaction

Every deploy/demo command must print and verify:

```text
chainId = 11155111
signer address = <expected disposable test address>
network = Ethereum Sepolia
```

If any command resolves to mainnet (`chainId = 1`), abort immediately.
